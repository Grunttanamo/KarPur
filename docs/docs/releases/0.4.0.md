# KarPur Launcher 0.4.0

KarPur builds the native game from your own legally obtained game files and console keys. **The launchers contain no game files, assets, dumps or keys.** Windows and Linux launchers are separate downloads in this release; the Linux/Steam Deck port remains experimental.

## Before starting a new game

Keep **Render scale at 1920×1080 until character creation is complete**. The character preview and ID photo can be misplaced or missing at other internal resolutions. After creating your character, choose another Render scale and restart the game. Window size and fullscreen can be set independently. For normal gameplay, keep the frame limit at **60 FPS**; higher limits can break battle transitions and move effects ([#85](https://github.com/Grunttanamo/KarPur/issues/85)).

## New in 0.4.0

- **Render scale:** 800×450, 854×480, 1280×720, 1920×1080, 2560×1440 and 3840×2160, plus experimental ultrawide, 4:3, 3:2, 16:10 and portrait formats. Violet 4.0.0 uses host-owned enlarged render targets without expanding its 268 MiB graphics pool or changing shadow allocation. Fullscreen now uses the monitor size regardless of the saved window size.
- **AMD FSR 2 on Vulkan:** included in the source package, with temporal anti-aliasing and optional window-sized output. No separate FSR download is needed. Moving objects may still leave trails. NVIDIA DLAA, DLSS and Frame Generation remain available where supported.
- **Lighting:** separate Off/Low/Medium/High Ambient occlusion and Indirect light settings. These screen-space effects use host GPU resources and leave the game's own memory pools unchanged.
- **Population and detail:** People detail and Pokémon detail distances up to 80 m, plus Town people shown at 12, 24, 36 or 48. Higher values may increase memory pressure; lower them if objects disappear.
- **Setup and compatibility:** `.xci` and `.nsp` base games are accepted. An NSP base, including a converted XCI, needs a firmware folder containing your console's system NCAs for the system fonts. Installation paths with spaces are supported. The two independent compatibility settings remain available: immediate GPU submission and Keep hot memory active (`hot_cool = 0`).
- **Launcher:** a dark text-entry dialog on Windows, clearer completed-build state, and a RecompLauncher manifest. The Linux AppImage carries the build tools and game source needed for installation on the Deck and includes Render scale, FSR 2, lighting, detail and population controls. Its Update page can find a published Linux AppImage.

## Issues and contributions

- [#46](https://github.com/Grunttanamo/KarPur/issues/46): added the requested 800×450 Render scale. Character creation at this size still needs the workaround above.
- [#69](https://github.com/Grunttanamo/KarPur/issues/69): the deferred-submit worker now uses the standard thread stack size after a reported NVIDIA driver stack overflow. The reporter's GPU is still needed to confirm the crash is fixed.
- [#71](https://github.com/Grunttanamo/KarPur/issues/71) and [#81](https://github.com/Grunttanamo/KarPur/issues/81): Linux graphics-memory synchronization improved. The maintainer's Deck test showed objects that were previously missing, but the broader AMD/Linux rendering reports are **not** considered fully resolved.
- [#74](https://github.com/Grunttanamo/KarPur/issues/74): removed the fixed 16,384-entry host limit for mod fields and added optional size and BNTX-only filters for texture packs. This does **not** remove the game's separate memory ceiling or guarantee that a complete 4K pack will load. Thanks to @babouch8 for the detailed report and tests.
- [#79](https://github.com/Grunttanamo/KarPur/issues/79): clarified when the firmware folder is required. Cartridge XCI bases do not need it; NSP bases do.
- Adapted [PR #76](https://github.com/Grunttanamo/KarPur/pull/76) from @mikeydoom: the Mods page follows `mod_files` in `karpur.ini`, including changes made outside the launcher. Adapted [PR #73](https://github.com/Grunttanamo/KarPur/pull/73) from @elripalda: RecompLauncher can use KarPur's build path and manifest. Its current manifest has no firmware-folder input, so use KarPur's own Setup tab for an NSP base.

## Still open

- Linux/Steam Deck is experimental. Texture corruption and missing scenery may still occur on other GPUs ([#71](https://github.com/Grunttanamo/KarPur/issues/71)); name entry also has an open Deck report ([#78](https://github.com/Grunttanamo/KarPur/issues/78)). Linux and Vulkan debugging reports and pull requests are welcome.
- AMD GPU crashes and visual issues remain under investigation ([#18](https://github.com/Grunttanamo/KarPur/issues/18), [#28](https://github.com/Grunttanamo/KarPur/issues/28)). The proposed import-arena experiment in [PR #50](https://github.com/Grunttanamo/KarPur/pull/50) is not included because its author reported crashes and corrupt input. [PR #75](https://github.com/Grunttanamo/KarPur/pull/75) is deferred.
- Ball-throw stutter ([#60](https://github.com/Grunttanamo/KarPur/issues/60)), the Electric Gym crash ([#72](https://github.com/Grunttanamo/KarPur/issues/72)), and a Scarlet startup report ([#84](https://github.com/Grunttanamo/KarPur/issues/84)) are not claimed fixed here. The reported workaround for #72 is a 30 FPS limit.

For setup and known limits, see the [README](https://github.com/Grunttanamo/KarPur/blob/main/README.md), [Windows launcher guide](https://github.com/Grunttanamo/KarPur/blob/main/docs/launcher.md) and [Linux launcher guide](https://github.com/Grunttanamo/KarPur/blob/main/docs/launcher-linux.md). Report problems in [GitHub Issues](https://github.com/Grunttanamo/KarPur/issues) with the full launcher or game log, system details and steps to reproduce.
