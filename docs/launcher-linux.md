# KarPur Launcher for Linux

This separate Linux launcher uses Avalonia and is built as `KarPur-Launcher-Linux-x86_64.AppImage`. For Steam Deck, use `KarPur-Linux-Launcher-0.3.8.AppImage`. Only the AppImage needs to be transferred. A complete folder package is also available as `KarPur-Launcher-Linux-x86_64.tar.gz`.

The launcher builds and repairs the native Linux game from your own dumps, starts an existing installation, manages graphics settings and saves, and shows the build log. Home uses the existing edition artwork and logos. Version 0.3.8 has an English interface and separate Controls and Update pages.

**Experimental:** Trees and other scenery can be missing on Steam Deck, and performance can vary. Home links to GitHub Issues and pull requests. Reports from people familiar with Linux and Vulkan are especially helpful when they include the device, graphics driver, and logs.

## Start the launcher

This release requires x86-64 Linux with glibc 2.38 or newer, such as Ubuntu 24.04 or newer. The minimum comes from the bundled SDL3 library. Make the AppImage executable:

```sh
chmod +x KarPur-Linux-Launcher-0.3.8.AppImage
```

Then start it:

```sh
./KarPur-Linux-Launcher-0.3.8.AppImage
```

If you use the folder package, extract the entire archive and start `linux-x64/KarPur-Launcher-Linux`. Keep `linux-x64/payload.zip` beside the executable. A launcher copied on its own from `bin/Release` cannot install the game.

If your system cannot mount AppImages with FUSE, use the extraction fallback:

```sh
./KarPur-Linux-Launcher-0.3.8.AppImage --appimage-extract-and-run
```

## Set up the game

In **Setup**, choose an installation folder and select your own base game, update, and `prod.keys` files. An NSP base game also requires a folder containing system NCAs from your own console. An NSP DLC is optional. **Install / update / repair** extracts the embedded source package and runs the build steps. Completed steps are reused on the next attempt.

The AppImage includes Python 3.14 and its required packages, SDL3, hactool, the shader translator, a portable Zig/Clang compiler, Ninja, and the Vulkan, Opus, VPX, and Zstd development libraries needed to build the game. Installing the game on Steam Deck does not require `apt` or `pacman` commands. The first build still needs time and free disk space. Graphics output uses your system's Vulkan driver.

The installation folder needs at least 30 GB of free space. The game, generated code, and saves stay in that writable folder. Launcher preferences are saved at `$XDG_CONFIG_HOME/karpur-linux/launcher.json`, or `~/.config/karpur-linux/launcher.json` when `XDG_CONFIG_HOME` is unset. Only paths are saved for the selected game files.

After a successful build, **Play** starts `build/game/karpur`. The launcher also places a runnable `KarPur-Linux-Launcher.AppImage` in the installation folder and creates application-menu and desktop shortcuts. To use an existing Linux installation, select its project folder in **Setup**. It must have the same `build/game` and `build/profile` structure.

## Steam Deck controls

**Controls** enables the Deck preset by default on SteamOS. It uses Nintendo button positions: Deck B maps to Switch A, A to B, Y to X, and X to Y. The left stick moves the character and the right stick controls the camera. L4 opens the PC menu; R4 is Plus and R5 is Minus when SDL exposes the rear buttons. When a controller is detected, the game ignores duplicate keyboard and mouse actions generated by Desktop Mode.

The **Controls** page can disable the preset and change stick and camera options. Actual Deck input still needs to be checked on the device; the local Linux tests have no Steam Deck controller.

## Updates

**Update** checks public GitHub releases for a Linux AppImage. When one is available, the launcher can download it, verify its SHA-256 file when provided, and install a runnable copy in the game folder. Restart the launcher afterwards. Until a Linux AppImage is published, the page says so.

## Add Linux to the existing GitHub release

Open the `v0.3.8` release and click the **Edit** pencil. Add `KarPur-Linux-Launcher-0.3.8.AppImage` and `KarPur-Linux-Launcher-0.3.8.AppImage.sha256` alongside the Windows asset, then click **Update release**. Keep the Windows file. Mark Linux support as experimental in the release notes and link to GitHub Issues and pull requests.

On a Deck with an older test launcher, start the new AppImage directly once. When it opens an existing installation, it replaces the old desktop shortcut with this version.

GitHub's automatic **Source code (zip/tar.gz)** archives remain tied to the original `v0.3.8` tag. A later tag, created after the Linux source commit, is needed for those archives to include Linux. Do not move the published tag.

## Settings and saves

Settings are written to `build/game/karpur.ini` while preserving existing comments and other values. Docked/Handheld selects the game's internal resolution; Window size selects the output size. The former Steam Deck experiments for `MEMORY=import` and compute shader translation have been removed. Old values in `launcher.json` no longer affect game launches. Removing them does not require rebuilding the game.

Save export creates a ZIP with `main` at its top level. Import checks the archive before replacing anything and backs up the current save under `build/profile/save-backup`. Import and export are disabled while the game is running. Let the game finish any pending save before exporting.

## Build the AppImage yourself (developers only)

You do not need this section to install the game. Building the AppImage requires the .NET 10 SDK, C/C++ tools, CMake, Git, Python, and `squashfs-tools` on the build system:

```sh
python3 tools/make_appimage.py
```

The script downloads pinned Python, SDL3, Zig, and AppImage components with SHA-256 verification, builds the native helper programs, and publishes the launcher with its .NET runtime. The AppImage and checksum are written to `dist/linux`; the complete folder package is built from the same bundled files. The source package comes from the project's source file list. Game files, generated game code, and ordinary build outputs are excluded, except for explicitly required helper programs built for Linux.

The same build works under WSL2. The Linux interface lives in `launcher-linux/` and reuses only the existing launcher's platform-independent INI reader. Mod management and controller navigation within the launcher itself are still open work.

Before this work, the native Violet runtime had no confirmed full Linux playthrough. Launcher checks with synthetic data do not replace a real playthrough. Verified build results are recorded in `docs/progress.md`.

The package layout follows [Avalonia's Linux deployment guidance](https://docs.avaloniaui.net/docs/deployment/linux) and uses the [AppImage Type 2 runtime](https://github.com/AppImage/type2-runtime).
